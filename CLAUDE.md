# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Heron is a Gaussian Process Regression (GPR) toolkit for gravitational waveform modelling. It produces waveform surrogates with built-in uncertainty estimates. The key innovation is returning full covariance matrices alongside mean predictions, enabling uncertainty-aware parameter estimation.

The current active model is `ExactGPSurrogate` (Matérn kernel + chirp-time warping) in `heron/models/gp/exact.py`. The older `HeronNonSpinningApproximantMatern` in `heron/models/gpytorch.py` is a legacy class kept for checkpoint backward-compatibility.

## Commands

**Run all tests:**
```bash
pytest tests/ -v
```

**Run a single test file:**
```bash
pytest tests/test_gp_exact.py -v
```

**Lint:**
```bash
flake8 heron tests
```

**Install in development mode:**
```bash
pip install -e ".[dev]"
pip install -e ".[lal]"   # for LAL waveform approximants
```

**Training a model:**
```bash
heron train --settings config.yaml
```

**Evaluating a trained model:**
```bash
heron evaluate --settings eval.yaml
```

## Architecture

### Data Types (`heron/types.py`)

- `Waveform`: numpy-only dataclass — `data`, `times`, `covariance`, `variance`, `std`
- `WaveformDict`: container for `plus`/`cross` polarisations; keyed by polarisation name

### Model Interface (`heron/models/base.py`)

`WaveformSurrogate` ABC enforces:
- `predict(parameters: dict) -> WaveformDict` — must return covariance, not just mean
- `save(path)` / `load(path)` classmethod for checkpoint round-trip
- `parameter_names: list[str]` and `parameter_bounds: dict[str, tuple]`

### ExactGPSurrogate (`heron/models/gp/exact.py`)

The primary production model. Architecture:
- Separate `_ExactGPModel` (GPyTorch `ExactGP`) for plus and cross polarisations
- Product Matérn kernel over each input dimension with `ScaleKernel`
- Time column warped via `ChirpTimeWarping` (power-law, best `alpha=0.625`)
- Output scaled by `output_scale=1e27` for numerical stability
- Checkpoint format is versioned: v2 saves unwarped training data; `_load_v1` handles old checkpoints from `HeronNonSpinningApproximantMatern`

**Critical hyperparameter constraints** — without these, L-BFGS collapses lengthscales to ~0.001 and the GP treats each training point independently:
- `ls_min_q` (default 0.0005): set to the q-spacing of your training grid. E.g., 5 mass ratios at spacing 0.2 → `ls_min_q=0.2`. Without it, the GP cannot interpolate between mass ratios and reverts to the prior at any untrained q.
- `ls_min_time` (default 0.0005): set to ~2× the *actual* warped-time training spacing for your specific grid — recompute it, don't copy a value from a different-density config. E.g., 200 samples → spacing 0.015 s → `ls_min_time=0.030`. Without it, the GP reverts to the prior between training times. **Getting this wrong the other way (too large) is also a real failure mode, not just too-small**: `dense30`'s original `ls_min_time=0.030` was copied unchanged from a 6× sparser grid and ended up 5-8× the grid's real spacing (0.0035-0.0062) — the trained lengthscale pinned exactly on it, capping the model's time resolution and producing a large, secular phase-evolution error at low-to-mid q (see Known Issues). Halving it to 0.015 fixed both the mean-function mismatch and, in a full nested-sampling posterior, a 67.6σ PE bias, with no accuracy trade-off elsewhere on the grid.
- `noise_floor_rel` (default 1e-6): set to 1e-3 when `ls_min > training_spacing` (highly correlated training points → ill-conditioned kernel matrix → CG NaN). This regularises K+σ²I without inflating the surrogate uncertainty in the likelihood.

**Optional non-stationary time kernel** (`merger_kernel: true`, `heron/models/gp/kernels.py::NonstationaryMaternKernel`): replaces the time dimension's plain `MaternKernel` with one whose lengthscale itself varies smoothly with (warped) time — long in the inspiral, short at/after merger — for the merger/ringdown reconstruction defect noted below. Extra YAML fields: `ls_min_time_merger` (near-merger lengthscale floor, ~2× real warped-time spacing, same rule as `ls_min_time`), `merger_center` (almost always `0.0` — every warping here maps raw t=0, merger, to warped 0 exactly, so this is known, not fitted), `merger_width_init` (transition width; `NonstationaryMaternKernel` derives a floor/ceiling of `width_init/4`/`width_init*3` from it automatically). `center` is a fixed buffer, not a learnable parameter, and `width` is bounded on both sides — see Known Issues for why (two rounds of the usual "collapse to the shortest lengthscale everywhere" pathology otherwise). Real matched-density result: ~20-25% mismatch reduction, not yet PE-validated — see Known Issues.

**Optional additive mass-ratio "floor" kernel** (`q_floor_kernel: true`, `heron/models/gp/kernels.py::build_additive_floor_kernel`): adds a fixed-lengthscale, learnable-amplitude-only long-range Matern component alongside the usual short one on every non-time dimension. Extra YAML fields: `q_floor_lengthscale` (defaults to 3× the dimension's data range if unset), `q_floor_outputscale_min`/`q_floor_outputscale_init` (floor/init for the long component's amplitude, default 0.05/0.1). **Implemented, tested, and NOT recommended** — proven both analytically and empirically to NOT flatten the training-grid-periodic K oscillation it was designed for; see Known Issues for the full negative result. Kept as a correctly-implemented, well-tested kernel option, not a fix for the log-det bias.

**Optional mass-ratio input warping** (`q_warping: eta`, `heron/models/gp/kernels.py::WarpedMaternKernel`/`symmetric_mass_ratio_warp`): warps the mass-ratio dimension's input through a fixed, monotonic `eta(q) = q/(1+q)^2` (symmetric mass ratio) before the kernel computes distances — the same idea `ChirpTimeWarping` already applies to time, now applied to mass ratio. Only the kernel's own distance computation sees the warped coordinate; the mean function still receives the raw (physical) mass ratio unchanged, so mean functions that generate physical waveforms (the LAL-approximant means) need no changes. **Recommended — real, substantial, NS-validated fix for the log-det bias** (see Known Issues): -6.2σ/+9.8σ/-16.0σ → +1.10σ/+0.50σ/-0.22σ at q=0.50/0.60/0.80 relative to the unsmoothed `lsminq006` baseline, clean unimodal posteriors. `eta` compresses q→1 (`eta'(q)→0`) relative to q→0 (`eta'(q)→1`), giving a longer effective lengthscale near q=1 and a shorter one near q=0 for a single stationary lengthscale in `eta`-space. Real risk to watch: on a grid sampled uniformly in raw q (like `dense30`), `eta`-spacing is drastically uneven (~100× more compressed near q=1 than near q=0.1), which can over-correlate the kernel matrix at the compressed end — needed an aggressive `noise_floor_rel` (0.3) to train cleanly; see the worked example `examples/train_phenomd_dense30_phase_amplitude_xas_qwarp_eta.yaml`.

**Training uses Cholesky, not CG** (enforced via `gpytorch.settings.max_cholesky_size(cholesky_size)`, default 2000, inside `_train()` and `predict()`). The "N ≤ ~2000" figure was a CPU-only assumption — on GPU, raising `cholesky_size` (e.g. to 6000) trains cleanly at much higher N; see `examples/train_phenomd_hf_dense30.yaml`. `SparseGPSurrogate` is still available for N beyond what GPU Cholesky can handle, but is no longer the first choice for N in the low thousands.

**`predict()` evaluates in float64, even though training is float32.** Training stays float32 (matches training data / existing checkpoints). But at trained lengthscales, `cond(K+σ²I)` is only mildly large (~1e5) — combined with float32's ~7 decimal digits that leaves just ~2-3 clean digits in `K_star @ alpha`, enough to look smooth at training-grid resolution but pure roundoff noise below it (query-point perturbations smaller than ~1e-3–1e-4 in mass ratio saw ~1.4e-3 relative output change regardless of step size — the signature of a noise floor, not a real derivative). Confirmed by recomputing the posterior mean from scratch in float64 (bypassing GPyTorch's caching entirely): the same finite difference scales cleanly linearly with step size down to 1e-6. Fix required no retraining — `ExactGPSurrogate._get_predict_models()` lazily deep-copies and `.double()`s the trained (float32) models the first time `predict()` is called, cached until the next `_train()`. See `scripts/gp_precision_probe.py`.

**Use the latent GP covariance in the likelihood** — `model(x)`, not `model.likelihood(model(x))`. LALSuite training data is noiseless; the trained σ²_noise is a regularisation artefact. The predictive (latent + noise) covariance inflates K unnecessarily. `predict()` already uses the latent distribution.

**Per-polarisation full-approximant mean, added 2026-07-17** (`mean_module_plus`/`mean_module_cross` constructor kwargs; YAML `mean_function.type: approximant`, e.g. `approximant: IMRPhenomXAS` — `heron/train.py` routes `model: exact` + this config to `LALApproximantPlusMean`/`LALApproximantCrossMean` automatically, one instance per polarisation since a waveform mean is inherently polarisation-specific, unlike the polarisation-agnostic PN means which still share one `mean_module`). Checkpoint format bumped to `format_version: 7` — stores `mean_functions: {"plus": ..., "cross": ...}` instead of the old single shared `mean_function`; `load()` still reads `format_version <= 6` checkpoints (falls back to applying the one shared mean to both polarisations).

**Required a second bug fix beyond the per-polarisation plumbing itself: a constant ~-2.15 rad phase-convention offset between the mean approximant and the training-target approximant, found when the first real checkpoint trained from this feature (`checkpoints/phenomd_nonspinning_dense30_exact_xas.pt`) scored WORSE than plain `ZeroMean` (median mismatch 3.3% vs `dense30_lsmin015`'s 0.84%) despite using a full-IMR mean that should only help.** Root-caused via `scripts/calibration_check.py`: the mean's raw `h_plus(t)` at real training points was *anti-correlated* (r≈-0.43 to -0.53) with the true training target at the same points. Two false leads first, both worth recording since they're easy mistakes to repeat: (1) comparing `argmax(|h_plus|)` between IMRPhenomD and IMRPhenomXAS suggested a several-ms, mass-ratio-dependent timing offset — this was an artefact of picking the single highest-magnitude *sample* on a fast-oscillating carrier (adjacent half-cycles have near-equal peak height, so argmax jitters between them); redoing it on the smooth amplitude *envelope* (`sqrt(hp²+hx²)`) instead showed both approximants' merger peaks already agree to <1ns — not a timing bug at all. (2) A brute-force cross-correlation time-shift search still capped out at r≈0.66 at its best-fit shift (~9ms) — also not the real mechanism, since the true fix (below) needs no time shift at all. The actual cause, found via a PSD-weighted matched-filter phase measurement (`heron.models.gp.mean.compute_phase_correction`): IMRPhenomD and IMRPhenomXAS differ by a phase offset that is **near-constant across mass ratio** (-2.24 to -2.13 rad measured over q=0.15-0.9) — a `phi_ref`/`f_ref` convention difference between the two LAL approximant families, not a physical or time-alignment effect. This constant is exactly what `heron.evaluation.mismatch.compute_overlap`'s fitting-factor maximisation is *designed* to absorb (so it never showed up in mismatch scans of the surrogate's final predictions) — but it is NOT invisible to a raw, unmaximised GP training residual: `cos(Φ)` vs `cos(Φ+2.15)` are two nearly-uncorrelated oscillating functions of comparable magnitude to the raw signal (measured r≈cos(2.15)≈-0.42, matching the observed correlation almost exactly), so an uncorrected mean handed the GP a *harder* fitting problem than `ZeroMean`, not an easier one. **Fix**: `LALApproximantPlusMean`/`LALApproximantCrossMean` no longer look up `h_plus`/`h_cross` directly from a raw LAL spline; they reconstruct `A·cos(Φ-c)`/`A·sin(Φ-c)` from the already-cached (log-amplitude, phase) splines with a `phase_correction` constant `c`, computed once via `compute_phase_correction()` (a one-off PSD-weighted matched-filter phase alignment at a single reference mass ratio — justified by the near-constant-across-q measurement above) and wired in automatically by `heron/train.py`'s `_build_mean_module`. Serialized in the checkpoint (`mean_to_config`/`mean_from_config`), defaults to `0.0` for backward compatibility. **Validated end-to-end after retraining** (`checkpoints/phenomd_nonspinning_dense30_exact_xas.pt`, same grid/hyperparameters, phase_correction≈-2.1475): median mismatch dropped from 3.3e-2 (broken) to **3.2e-3** — now genuinely better than `ZeroMean`'s 0.84%, and residual magnitudes (per `calibration_check.py`) dropped roughly an order of magnitude across every q tested. Trained lengthscales also moved noticeably off their `ls_min_q` floor for the first time in this checkpoint family (`ls_q`≈0.033/0.042 for plus/cross, vs the previous checkpoint's exact 0.030 pin) — consistent with the GP no longer needing pathologically short lengthscales to chase an uncorrelated, oscillating residual.

**K-calibration comparison, ExactGPSurrogate+XAS vs PhaseAmplitudeGPSurrogate+XAS (2026-07-17, `scripts/calibration_check.py`, on the fixed checkpoint), matched training data/hyperparameters.** GP-reported posterior variance K divided by the true squared residual (surrogate mean vs true oracle waveform), in each model's *native* representation space (strain for exact; log-amplitude/phase for phase-amplitude — not the phase-amplitude model's delta-method-propagated strain covariance, which only approximates the true native calibration). Median K/resid² ratios: exact ≈0.3-33 across q=0.3/0.5/0.7/0.9 (both polarisations); phase-amplitude's log-amplitude/phase GPs ≈1e3-1e8 over the same q's — 3-8 orders of magnitude more overdispersed, consistent with (and now generalising) the "K is 1000-4000x larger than the real residual" finding from the grid-snap investigation below. **This is not simply a property of fitting an XAS-mean GP in general — it is much worse specifically in the phase/log-amplitude decomposition**, a genuine, actionable difference between the two representations' uncertainty calibration, not yet explained.

**NS-validated 2026-07-17, result inconclusive on the calibration question — confounded by the same high-SNR mismatch-dominance issue flagged (and never resolved) after the `lsmin0075` q-scan.** Matched-injection (inject IMRPhenomXAS, recover with K/without K, q=0.50/0.60/0.80, SNR≈285-322) against both fixed checkpoints (`exact_xas_lsminq006`, `phase_amplitude_xas_lsminq006`) gave 88σ-1247σ bias **with and without K, for both representations, at every q** — since without-K is plain matched filtering with zero GP-uncertainty involvement, this rules out log-det marginalisation as the cause here, not confirms it. Root cause: mismatch between each surrogate and the raw injected IMRPhenomXAS signal is 0.7-1.1% at every q for both checkpoints — ~1000-2000x above the `1/(2·SNR²)` ≈ 5.6e-6 threshold for unbiased recovery at this SNR, the same "sub-1% mismatch is ~1000x too large at SNR~300" phenomenon already on record (see the `qscan_lsmin0075_htcondor` entry below), not a new defect and not related to log-det marginalisation or to the phase-correction fix above. **The K-calibration difference measured above is real and still stands, but this test does not show whether it reduces PE bias in practice — that requires rerunning at realistic SNR (~10-30), which CLAUDE.md already recommended after the `lsmin0075` q-scan and which still has not been done.**

### PhaseAmplitudeGPSurrogate (`heron/models/gp/phase_amplitude.py`)

An alternative to `ExactGPSurrogate` — same `WaveformSurrogate` interface (drop-in wherever a surrogate is consumed, e.g. `gw_likelihood.py`, `evaluate.py`), not a replacement. Motivation: raw strain is oscillatory, a structurally poor match for a Matérn kernel (see `design.md`'s "Architectural fork" note and the low-*q* phase-drift bug below). Instead of fitting `h(q,t)` directly, it decomposes into amplitude and phase and fits two independent, non-oscillatory GPs:

- **Convention**: `h_plus - i·h_cross = A(t)·e^{-iΦ(t)}` ⇒ `h_plus = A·cosΦ`, `h_cross = A·sinΦ`; inverted as `Φ = atan2(h_cross, h_plus)`. `strain_to_amplitude_phase()` groups training rows by mass ratio and sorts by time before `np.unwrap`-ing the phase — unwrapping across mass ratios or out of time order produces a sawtooth, not a smooth target.
- GPs are fit on `log(A)` (not `A`) — strain amplitude spans decades, and log-amplitude is already well-scaled (~O(-50..0)), same for phase (~O(-1000..0)) — **no `output_scale`** needed or accepted by this model (unlike `ExactGPSurrogate`'s `output_scale=1e27`, which exists specifically to rescale raw ~1e-21 strain).
- `predict()` reconstructs `h_plus`/`h_cross` and propagates uncertainty from the (independent) log-amplitude/phase covariances via the **delta method** (first-order/linearised error propagation — a diagonal Jacobian congruence, since each output sample depends only on the logA/phase value at that same time). This is an approximation: accurate while `σ_Φ ≲ 0.3 rad`, degrades for larger phase uncertainty since `cos`/`sin` are only linearised locally. Not yet cross-checked against Monte Carlo sampling.
- Mean functions are separate for each GP (`mean_module_amplitude`/`mean_module_phase`, YAML: `mean_function_amplitude`/`mean_function_phase`), reusing the same PN physics as the strain-domain means via a shared helper (`_pn_amplitude_and_phase` in `mean.py`) — see below.
- **Tested against the q≲0.4 phase-drift bug (2026-07-15) — hypothesis confirmed for the inspiral specifically, but a new, currently-dominant merger/ringdown defect makes the representation not yet competitive overall.** Not yet wired into `training.mode: active` (active learning) — only `fixed`/`data` modes are supported.

**Two real training-stability bugs found and fixed while getting the first real (non-synthetic) training run working** (`examples/train_phenomd_hf_dense10_phase_amplitude.yaml`, IMRPhenomD, 10 mass ratios):
1. `_pn_amplitude_and_phase`'s "zero after merger" behaviour (harmless for the combined strain mean — the residual there is just "actual minus zero," same order of magnitude as the strain itself) is catastrophic for a *log*-amplitude mean: `log(0)` diverges right at the highest-density, peak-amplitude training region, creating a huge sharp residual discontinuity that caused `NotPSDError` (Cholesky failure) within the first L-BFGS step. Fixed with a dedicated `_pn_log_amplitude` helper (used only by `NewtonianInspiralAmplitudeMean`/`TaylorT2AmplitudeMean`) that clamps `tau` to a small positive floor instead of hard-zeroing past merger — the amplitude saturates at its near-merger value rather than jumping to ~`log(1e-30)`.
2. Even with that fixed, training still crashed a bit later — root cause was `ls_min_time` copied unchanged from `examples/train_phenomd_hf_dense10.yaml` (0.030), which is 4-8x this grid's actual warped-time spacing (~0.0035-0.0088 s, measured directly per mass ratio) — the same general "copied `ls_min_time` from a different-density config" pitfall documented above for `ExactGPSurrogate`'s `dense30`. Recomputing it (0.018, ~2x the largest per-q spacing) trains without crashing.

Even with both fixes, convergence is slow (L-BFGS line search burns many evaluations per outer step with little loss improvement) and this representation's hyperparameters have had nowhere near the tuning pass `ExactGPSurrogate` has — treat the example config as a verified-not-to-crash starting point, not a tuned one. Also observed directly: unwrapped phase, evaluated at fixed warped-time across mass ratios, varies by 100s of radians between neighbouring q's (inspiral duration varies ~3x across q at fixed total mass, so very different cycle counts accumulate) — this is a steep, possibly kernel-floor-limited q-dependence for the phase GP specifically, not yet investigated further.

**Density-matched comparison against ExactGPSurrogate (2026-07-15), motivated by the time-domain model's overfitting-flavoured failures at small `ls_min_time` (see the lsmin0075-reversal and SNR~100 universal-attractor entries below).** Trained a `PhaseAmplitudeGPSurrogate` on the exact same 30-mass-ratio/N=6000 grid as the current best time-domain checkpoint (`checkpoints/phenomd_nonspinning_dense30_lsmin015.pt`), same `ls_min_q=0.03`/`ls_min_time=0.015`/`noise_floor_rel=1e-3` (`examples/train_phenomd_hf_dense30_phase_amplitude.yaml`, `checkpoints/phenomd_nonspinning_dense30_phase_amplitude.pt`, trained on wiay GPU, both polarisations converged cleanly — final losses 2.659/2.599, no crashes). `scripts/mismatch_vs_mass_ratio.py`/`scripts/probe_phase_drift.py` were generalised to auto-detect the checkpoint's model class (`model_class` field) so either representation can be pointed at the same scripts.

Two-part result, not a simple win or loss:
1. **The core hypothesis holds for the inspiral**: `scripts/probe_phase_drift.py` across q=0.25/0.30/0.70/0.90 shows flat, small phase-drift spans (0.044-0.071 cycles) with no q-dependent "hump" — comparable to `ExactGPSurrogate`'s own post-fix `lsmin015` numbers, and nothing like its original 2.5-10.9 cycle blowup at low-mid q. The phase-amplitude decomposition genuinely does sidestep the secular phase-drift/overfitting failure mode by construction, as hypothesised.
2. **But a new, currently-dominant defect swamps that win: merger/ringdown reconstruction is badly wrong, roughly uniformly across q.** `mismatch_vs_mass_ratio.py`'s full-q scan (same fixed `-0.5s..+0.02s` window as used for all `ExactGPSurrogate` numbers above) gives a **flat 34-43% mismatch across the entire q=0.10-0.97 range** — no q-dependent hump at all, unlike every `ExactGPSurrogate` checkpoint tested. Progressively trimming the evaluation window's upper bound (`+0.02s→0.0s→-0.01s→-0.05s`, i.e. cutting merger/ringdown out) at q=0.30/0.70/0.95 dropped mismatch from ~35-43% to ~3-14% — most of the flat, uniform badness lives in the last ~20ms around and after merger, not in the inspiral. Direct inspection of one case (q=0.70): amplitude ratio surrogate/reference is ~0.86-1.3 in the low-power ringdown tail (noisy but not absurd) while the **unwrapped phase diverges by 23-36 rad within ~20ms after merger** (phase_ref=-103.5 vs phase_surr=-80.4 rad at t=+0.013s, widening to -116.0 vs -80.5 at t=+0.02s) — a real, large reconstruction failure specifically in the post-merger segment, present at every q tested. Even with merger/ringdown excluded, the remaining inspiral-only mismatch (~3-14%) is still 2-4 orders of magnitude worse than `ExactGPSurrogate`'s `lsmin015` in its good region (1e-5-1e-2 at q=0.7/0.95 under the same windowing) — so this is not simply "great inspiral, bad merger," the inspiral fit itself is also currently far behind the tuned time-domain model.

**Practical implication [SUPERSEDED 2026-07-15 — see the IMRPhenomXAS-mean entry below; the "flat 34-43% mismatch" above was a measurement/loading artifact stack, not a representation failure]: do not switch to `PhaseAmplitudeGPSurrogate` for PE work yet — at matched training density it is currently worse overall than `ExactGPSurrogate`'s `dense30_lsmin015`, despite cleanly solving the specific secular phase-drift defect it was designed to address.** The merger/ringdown failure is the natural next thing to root-cause before any nested-sampling test on this representation would be worthwhile (candidates, untested: the log-amplitude mean's near-merger clamping creating a residual shape the GP can't follow at `ls_min_time=0.015`; the phase's rate-of-change spiking sharply through merger while the model still uses one global time lengthscale tuned for the smoother inspiral; insufficient training-sample density right at merger relative to how fast phase/log-amplitude actually vary there). Results: `results/mismatch_vs_q_dense30_phase_amplitude.{npz,png}`.

**Mean-function upgrade tested and ruled out (2026-07-15), without training — `scripts/probe_phase_mean_residuals.py` evaluates the PN means directly against the decomposed dense30 training targets.** The hypothesis was that the phase domain escapes the strain-domain PN-mean failure (documented in the mean-function memory: r≈−0.06 at M=60 because `cos(Φ_PN)` decorrelates) since a few radians of PN error out of ~1000 rad of unwrapped phase would still be an excellent mean. Measured: at M=60 the in-band accumulated phase is only ~O(100s) rad and the PN truncation error is comparable — corr(target, mean)≈+0.67 and the per-q-demeaned inspiral phase residual drops just 94.2→82.4 rad with `TaylorT2PhaseMean` (85.8 Newtonian, so 1PN buys ~4% over Newtonian); the log-amplitude mean removes ~8% (2.33→2.15) and exactly nothing post-merger (frozen clamp: residual std = target std). **Also ruled out: the first "candidates, untested" item above in its phase-mean form — `_pn_amplitude_and_phase`'s zero-after-merger cutoff is *continuous* for the phase (PN convention pins Φ=0 at merger; measured residual jump at merger ≤2.5 rad, median 0.7), so the phase mean is not the source of the merger/ringdown defect.** A ready-to-run confirmation config exists (`examples/train_phenomd_hf_dense30_phase_amplitude_taylort2.yaml`, expected null result) but was deliberately not trained. Conclusion: PN means are a dead end at M=60 in *both* representations; the live escalations remain a full IMR approximant as mean (multi-fidelity) or testing at lower total mass where PN is valid.

**BREAKTHROUGH (2026-07-15) — IMRPhenomXAS as the mean function (`LALApproximantAmplitudeMean`/`LALApproximantPhaseMean` in `mean.py`, YAML `type: approximant` + `approximant: IMRPhenomXAS`): median mismatch 9.6e-5 across the full q=0.12-0.95 scan, 100% PE-grade (<1e-2), 93% detection-grade (<1e-3), worst point 4.5e-3 at q=0.287 (the known Nyquist corner) — two orders of magnitude better than `dense30_lsmin015` (median 8.4e-3) at identical training density, and the low-q "hump" is gone entirely.** `scripts/probe_phase_drift.py` shows 0.000 cycles of drift at q=0.25/0.30/0.70/0.90 with ~1e-4 relative amplitude errors. Checkpoint: `checkpoints/phenomd_nonspinning_dense30_phase_amplitude_xas.pt` (trained on wiay GPU, `examples/train_phenomd_hf_dense30_phase_amplitude_xas.yaml`, `mode: data` on the exact same N=6000 HDF5 as the newtonian-mean checkpoint — the mean function is the only difference). Why it works where PN means failed: the XAS mean tracks the PhenomD targets to ~0.1 rad (phase, inspiral) / 0.0006-0.0035 (logA, in-window) so the GP fits only the small smooth D-XAS difference; the mean covers merger/ringdown natively; and it enables mean-referenced phase unwrapping (below). Implementation notes: the mean is CPU/LAL-backed and non-differentiable — fine because GP means have no trainable parameters and MLL gradients never differentiate through the mean's inputs; per-q waveforms and forward results are cached (bounded) so training/predict cost is negligible; `predict()` generates one XAS waveform per new q. NOT supported for the strain-domain `ExactGPSurrogate` (it shares a single mean module between plus and cross, and a waveform mean is polarisation-specific — `_build_mean_module` raises with an explanatory error).

**Getting there required finding and fixing FOUR stacked bugs — each documented with regression tests; all previously-published phase-amplitude numbers were corrupted by the first three:**
1. **Silent mean-function drop on checkpoint load** (`PhaseAmplitudeGPSurrogate.load()` and `ExactGPSurrogate.load()` never rebuilt mean modules; mean functions have no trainable parameters so `load_state_dict` can't restore or even detect them). Every post-load evaluation of the newtonian-mean dense30 checkpoint ran with ZeroMean — this alone accounts for most of the "flat 34-43% mismatch": with means restored (repaired copy `checkpoints/phenomd_nonspinning_dense30_phase_amplitude_meanfix.pt`) it drops to median 6.6e-2. Fixed: checkpoints now serialize `mean_functions`/`mean_function` configs (`mean_to_config`/`mean_from_config` in `mean.py`, phase-amplitude format_version 2, exact format_version 6); loading a v1 phase-amplitude checkpoint warns loudly.
2. **Sparse-grid phase-target corruption**: `strain_to_amplitude_phase` unwrapped the atan2 phase on the 200-samples-per-q training grid, but the warped-uniform grid's per-sample phase advance exceeds pi near merger at EVERY q (7-9 samples/q; 177/199 at q=0.10) — `np.unwrap` silently deleted cycles, so the phase targets themselves were wrong through merger everywhere (matching the "23-36 rad post-merger divergence") and wrong nearly everywhere at q<=0.16. Fixed via **mean-referenced unwrapping** (auto-enabled when the phase mean is a `_LALApproximantMeanBase`): wrap the principal phase relative to the mean, unwrap the slowly-varying difference (~0.1 rad/sample), add the mean back; per-q 2*pi branch canonicalised to the median so isolated taper artefacts can't park one q a full branch away from its neighbours. Requires a mean accurate to << pi per sample step — only approximant means qualify, so zero/PN-mean models keep the old (aliased at high sample-rate-deficit) behaviour.
3. **`compute_overlap` time-shift maximisation undervalued the overlap at any nonzero best-fit phase offset**: it used `np.fft.irfft` on the one-sided cross-spectrum, which imposes conjugate symmetry and returns only Re z(tau); |Re z| = |z| only when the optimal phase is 0/pi. Comparing waveform pairs with a real constant phase offset (D vs XAS: ~2 rad) reported 23% mismatch where the true windowed fitting-factor mismatch is 1.4% (coarse grid). Fixed with a complex one-sided ifft whose zero-lag exactly matches the maximize_time=False branch; regression tests in `tests/test_evaluators.py`. Surrogate-vs-D scans were essentially unaffected (their phase offsets are ~0), so `ExactGPSurrogate` history stands; but any past cross-approximant or phase-offset comparison made with this function is suspect.
4. **Noise floor scaled by var(y) instead of var(y - mean)** (`_ExactGPModel.__init__`): with an accurate mean, var(raw phase target) ~ (141 rad)^2 put the noise floor (noise_floor_rel=1e-3) ~5 orders of magnitude above the entire 0.1-rad residual — the GP was forced to explain ALL of its signal as observation noise and predicted ~= the bare mean (first XAS training run scored only ~1.4e-2, i.e. raw-XAS quality; the GP added nothing). Fixed: all data-driven scales (noise floor, outputscale/noise init) now use the residual variance; no-mean models are unchanged (residual == target).

### DeltaGPSurrogate (`heron/models/gp/delta.py`)

A third model (2026-07-15), same `WaveformSurrogate` interface. The GP does not model the waveform at all: a cheap **base approximant** (e.g. IMRPhenomD) is evaluated exactly at predict time, and two GPs fit only the **residual between the training oracle and that base**, decomposed as Δlog A and ΔΦ (per-mass-ratio phase-aligned). Motivation: wherever both models agree on the bulk phasing (both NR-calibrated), the residual is small and *slowly varying* — a structurally good Matérn target, sidestepping the carrier-frequency-oscillation problem behind the strain-domain model's floor-pinned lengthscales and secular phase drift. The returned covariance K is the delta GPs' posterior — i.e. **approximant systematics** (uncertainty about the oracle−base difference), not surrogate self-interpolation error.

- Mathematically equivalent to `PhaseAmplitudeGPSurrogate` with `LALApproximant{Amplitude,Phase}Mean` means; differences are engineering: residual targets are explicit arrays built once by `compute_delta_targets()` (inspectable; logged ranges; warns if ΔΦ span >50 rad, the signature of a convention mismatch), phase alignment is explicit (`phase_alignment: anchor|branch|none` — anchor zeroes each q's earliest-time ΔΦ; branch removes only 2π unwrap offsets), and the base can be any `time_domain`-interface object, not just registry names (tests use analytic toys, no lalsuite).
- Subclasses `PhaseAmplitudeGPSurrogate` to reuse `_train`/`_get_predict_models`; overrides `__init__`/`predict`/`save`/`load`. Delta GPs use ZeroMean — far from training data the prediction degrades gracefully to the exact base approximant with the prior's uncertainty.
- Checkpoints store the base approximant *by name*; `load(path, base_approximant=instance)` overrides for non-registry bases.
- YAML: `model: delta`, `approximant:` is the oracle, plus `base_approximant`, `phase_alignment`, `f_low`. No `output_scale`, no mean-function keys. Example: `examples/train_delta_phenomd_xas_dense10.yaml` (oracle IMRPhenomXAS, base IMRPhenomD, dense10 grid for comparability). **Not yet trained on real LAL data** — the example config is untested end-to-end; trained lengthscales are expected to sit *above* their floors here (smooth targets) — floor-pinning would be a red flag for this model, unlike the chronic pinning in the strain-domain models.

### Time Warping (`heron/models/warping.py`)

- `ChirpTimeWarping(alpha, t_ref)`: `t_warp = sign(t) * |t/t_ref|^alpha * t_ref`
  - Best empirical config: `alpha=0.625`; default `alpha=0.375` (Newtonian)
- `SimpleWarping(scale)`: linear compression of `t < 0`
- `get_warping(type, **kwargs)` factory — use this everywhere, not constructors directly

### Training (`heron/train.py`, `heron/training/`)

Three training modes (set `training.mode` in YAML):
- `fixed`: grid of mass ratios, sampled uniformly in warped time
- `active`: iterative uncertainty-guided refinement (`active_learning_loop`)
- `data`: load pre-existing HDF5 `TrainingSet`

`TrainingSet` (`heron/training/dataset.py`):
- Stores `x` (N, D), `y_plus` (N,), `y_cross` (N,); last column of x is always time
- HDF5 save/load; `append()` for incremental active learning

### GW Likelihood (`heron/gw_likelihood.py`, `heron/noise.py`, `heron/detector.py`)

The GP-marginalised GW likelihood `p(d|θ) = N(d | μ(θ), C + K(θ))`:
- `GWLikelihood`: wraps the surrogate; computes `log p(d|θ)` for one detector
- `use_waveform_uncertainty=True/False` switches GP-marginalised vs. standard matched-filter
- Data and signal are HP-filtered at `f_low`; noise covariance C from `noise_covariance(times, psd_fn, f_low)`
- K is approximated as **diagonal** (HP filtering creates negative eigenvalues in the full projected K — diagonal stays positive-definite)
- GP predict casts to `float64` before dividing by `output_scale²` — float32 underflows at 1e-42

**The log-determinant bias**: the likelihood has two competing terms — a data-fit term (peaks at true θ) and a log-det term `−½ log|C+K(θ)|` (penalises high-K regions, i.e. pulls posteriors toward training points). When K/C is large *and* varies strongly with θ (sparse training grid), the log-det term dominates and the posterior is biased toward training parameters. Rule of thumb:
- K_prior/C ≈ SNR²/N_samples (e.g., SNR=163, N=256 → K_prior/C ≈ 144)
- K_mid/C < 1 requires q-spacing ≤ 0.03 (30 qs); unbiased posterior requires q-spacing ≤ 0.02 (45 qs)
- At high SNR (>30), a training grid of 5–10 mass ratios is insufficient for unbiased q PE

### Evaluation (`heron/evaluate.py`, `heron/evaluation/`)

- `MismatchEvaluator`: computes overlap mismatch between surrogate and reference
- `CalibrationEvaluator`: checks GP uncertainty calibration against reference
- `EvaluationReport`: collects both, writes summary + optional matplotlib plots

## Training YAML Schema

```yaml
training:
  mode: fixed           # fixed | active | data
  approximant: IMRPhenomPv2
  mass_ratios: [0.3, 0.5, 0.7, 1.0]
  total_mass: 60.0      # solar masses
  distance: 100.0       # Mpc
  n_samples: 200        # time samples per mass ratio
  warping:
    type: chirp
    alpha: 0.625        # best empirical value; 0.375 is Newtonian
  model: exact          # exact | sparse | phase_amplitude | delta
  nu: 2.5
  output_scale: 1.0e27
  optimizer: lbfgs      # lbfgs (default) | adam
  iterations: 80        # L-BFGS outer steps; ~80 usually enough
  checkpoint: checkpoints/model.pt
  # Lengthscale lower bounds — MUST be set; see ExactGPSurrogate notes above
  ls_min_q: 0.2         # set to q-spacing of mass_ratios grid
  ls_min_time: 0.030    # set to ~2× warped-time training spacing
  noise_floor_rel: 1.0e-3  # raise from 1e-6 when ls_min > training spacing
  # optional:
  device: cpu           # or cuda
  save_training_data: checkpoints/training.h5
  mean_function:
    type: newtonian     # zero | newtonian | taylort2
  # optional non-stationary time kernel (model: exact only) — see
  # ExactGPSurrogate notes above
  merger_kernel: false
  ls_min_time_merger: 0.01   # near-merger lengthscale floor, ~2x real spacing
  merger_center: 0.0         # almost always 0.0 -- merger is exactly t=0
  merger_width_init: 0.03
```

A worked example: `examples/train_phenomd_hf.yaml` (5 mass ratios, N=1000, ls_min_q=0.2, ls_min_time=0.030).

- **Follow-up — root cause is a secular phase-evolution-rate error, not undersampling or a windowing artefact; strongly implicates the fixed-scale `ChirpTimeWarping` + separable kernel, confirming the "warping assumptions breaking down" hypothesis.** Three checks (`scripts/probe_phase_drift.py`, new; `dense30`, which loads locally — `dense45` still hits the format-incompatibility below): (1) *not raw undersampling* — comparing each q's uniform-in-warped-time training-sample spacing against the local Nyquist limit set by the true instantaneous GW frequency shows the training data itself resolves the oscillation adequately for q≥0.2 (only q=0.10 is genuinely Nyquist-undersampled near merger); yet mismatch is already 35-65% for q=0.2-0.4, so undersampling can't be the (main) driver. (2) *not the fixed evaluation window* — re-running `mismatch_vs_mass_ratio.py`'s comparison with a native, untruncated per-q window (same dt, full duration, no `-0.5s..0.02s` clipping) gives mismatch equal to or *worse* than the fixed-window numbers at every q tested (e.g. q=0.30: 45.7%→60.1% mismatch), ruling out truncation as the cause. (3) *is* a phase-rate defect — `scripts/probe_phase_drift.py` isolates the pre-merger inspiral and tracks the (mean-subtracted) surrogate-vs-reference phase residual: at q=0.90 (good fit, 2.5% mismatch) the residual stays flat within 0.03 cycles across the whole inspiral; at q=0.30 (bad fit, ~50% mismatch) the residual *drifts monotonically*, accumulating 2.5 full cycles of phase error over the same inspiral, with amplitude undershooting the truth by up to 95% near merger. A monotonically-accumulating (secular) phase error is the signature of the surrogate's phase-evolution *rate* being wrong for that q — not of noisy/local interpolation, which would look flat or oscillate around zero. Two structural candidates converge on the same explanation: `ChirpTimeWarping` applies one global `(alpha=0.625, t_ref=0.1s)` to every mass ratio, but the true inspiral chirp timescale is mass-ratio-dependent (chirp mass varies ~2x from q=0.1 to q≈1 at fixed `total_mass=60`, matching the ~2.7x duration spread already on record) — a single global warping cannot be the physically self-similar transform for every q simultaneously. Compounding this, the product/separable Matérn kernel `k((q,t),(q',t')) = k_q(q,q')·k_t(t,t')` has no q×time interaction term, so one global (and, per the checkpoint, floor-pinned: trained `ls_time = 0.030003 ≈ ls_min_time`) time lengthscale must serve the whole q range — the optimizer is pushing against the floor, not converging inside it. [[mean_function_experiment]] independently confirms `ZeroMean` is carrying 100% of the phase-modelling burden here (a Newtonian/1PN mean was already found to decorrelate at this mass, r≈-0.07), so there's no physical fallback when the kernel's single global timescale is wrong for a given q. - **Merger/ringdown non-stationary-kernel experiment (2026-07-15) — real, modest improvement; not a fix.** Motivated by the recurring observation (this file, `PhaseAmplitudeGPSurrogate` section) that merger/ringdown reconstruction is bad across every representation tried so far, and the hypothesis that a single global time lengthscale (the separable product-Matern kernel `ExactGPSurrogate` has always used) can't represent both the slowly-varying inspiral and the fast merger/ringdown transient at once — the same "one global timescale can't fit a genuinely multi-timescale signal" mechanism already implicated in the low-q secular phase-drift saga above, just playing out at the *opposite* end of the waveform (merger, not low-q). Rather than another time-warping revision (already tried twice for the low-q version of this problem, both net-negative — see `MassRatioChirpTimeWarping` above), implemented `NonstationaryMaternKernel` (`heron/models/gp/kernels.py`): a Paciorek & Schervish (2004)-style kernel whose *lengthscale itself* is a smooth function of warped time, `l(t) = lengthscale_near + (lengthscale_far - lengthscale_near) * sigmoid((center - t)/width)`, positive-definite for any smooth positive `l(.)`. Used only on the time dimension (`merger_kernel: true` in YAML), everything else (mass-ratio kernel, warping, mean function) unchanged.
  - **Two rounds of the same "collapse toward the shortest lengthscale everywhere" pathology already well-documented elsewhere in this file, now expressed through the kernel's new parameters instead of the old `ls_min`.** (1) Made `center` (the near/far transition location) learnable, bounded first to the full data range, then to ±20×width with an informative Normal prior: both still collapsed under L-BFGS, pinning `center` at the edge of whatever range was allowed — confirmed on real N=2000 training data, where a `center` pinned at warped -0.4 unwarped to **t=-0.92s**, deep in the inspiral, nowhere near merger. Root cause: gpytorch's `ExactMarginalLogLikelihood` divides the *entire* loss (data-fit + prior log-probs) by `num_data`, so a prior's absolute pull is O(1) while the data-fit term grows with N — priors that look fine on paper are negligible at real training sizes. (2) Fixed `center` at the known-exact physical merger time (t=0 maps to warped 0 for every warping in this codebase, by construction — nothing to learn) and just capped `width`'s *both* sides (`Interval(min_width, max_width)`, not a floor alone): this is what actually held. Two lessons for reuse: soft priors on a nonstationary kernel's shape parameters are not a substitute for hard bounds at this codebase's training scale; and a "collapse to the floor" failure mode isn't specific to a single lengthscale parameter, it recurs through *any* free parameter that can effectively shrink the model's fitted timescale.
  - **Matched-density comparison against `dense30_lsmin015`** (same 30-q/N=6000 grid, same `ls_min_q=0.03`/`ls_min_time=0.015`/`noise_floor_rel=1e-3`; `ls_min_time_merger=0.01` ≈2× dense30's real per-q warped-time spacing, same rule used to derive `ls_min_time` itself; `merger_width_init=0.03`, chosen since unwarp(±0.037)≈±20ms physical, the merger/ringdown window already implicated in the `PhaseAmplitudeGPSurrogate` merger defect above — `examples/train_phenomd_hf_dense30_merger_kernel.yaml`, `checkpoints/phenomd_nonspinning_dense30_merger_kernel.pt`, trained on wiay GPU). - **Log-det bias isolated from every prior confound, root-caused, and partially fixed (2026-07-18/19) — a real, validated improvement, not a full close-out.** The log-det-bias saga above accumulated several confounded high-SNR tests over time (grid-snap, wrong-approximant-family injections, sub-1% mismatch swamping everything at SNR~300). Two of the "next step" experiments flagged in earlier entries (the matched-injection tests, and rerunning them at lower SNR) turned out to be a dead end: `checkpoints/phenomd_nonspinning_dense30_{exact,phase_amplitude}_xas_lsminq006.pt` only use IMRPhenomXAS as the *prior mean* — their GP correction is fit against IMRPhenomD training targets, so the surrogate's actual reproduction target is D, not XAS. Injecting XAS (the "matched" test) reintroduces a genuine ~0.3-1.1% D-vs-XAS approximant systematic that explains the 88-1247σ bias present identically with and without K reported in the entry above — not log-det, and not fixable by lowering SNR. **The correctly-matched test already existed, just under-analysed**: the plain D-injected with-K/no-K comparison on the `ls_min_q=0.06` phase-amplitude+XAS checkpoint (~1e-4 self-consistency mismatch, so not confounded by gross template error) at q=0.50/0.60/0.80, SNR 285-334: with-K displacement is -6.2σ/+9.8σ/-16.0σ vs no-K's -0.6σ/+1.0σ/-1.9σ — a clean ~8-10× inflation from K-marginalisation at every point, the log-det mechanism isolated for the first time from every other confound in this file.
  - **Root cause confirmed directly, not just inferred**: scanning the GP's own reported variance across mass ratio near a training node on this checkpoint (`predict()` at q=0.46-0.55) shows variance minimised almost exactly at training nodes (q=0.49, 0.52, spacing 0.03) and ~2× higher at the antinode between them (q≈0.505) — a periodic oscillation with period equal to the training grid spacing, still present after `ls_min_q` was raised 0.03→0.06. This is not a residual tuning bug; it is mathematically inherent to any GP posterior (variance is always minimised at/near training inputs). Raising `ls_min_q` only shrinks the oscillation's relative depth (450-500× → ~1.6-2×, see the grid-snap entry two below); it structurally cannot remove it, which is why the with-K bias direction kept tracking the nearest training node even after that fix.
  - **Fix implemented and NS-validated: `k_smoothing_offsets`/`k_smoothing_param` on `GWLikelihood` (`heron/gw_likelihood.py`)** — evaluates `surrogate.predict()` at the query point plus a handful of nearby mass-ratio offsets and takes the elementwise-max variance across all of them before it reaches the likelihood, removing the training-grid-periodic dip while preserving genuine larger-scale variation of K with θ. Disabled by default (empty offset list ⇒ identical to prior behaviour). Costs one extra `predict()` call per offset per likelihood evaluation. `scripts/injection_nested_sampling.py` exposes `--k-smoothing-grid-spacing` (derives 4 symmetric offsets spanning ± half the given spacing); new `scripts/profile_scan_k_smoothing.py` does a cheap fixed-tc log-likelihood profile scan (no sampler) for a same-session sanity check before committing to a full NS run.
  - **Full NS validation** (HTCondor, wiay/puck, nlive=250, `results/injection_ns_pa_xas_lsminq006_smoothed_q0{50,60,80}.npz`, `--k-smoothing-grid-spacing 0.03`): absolute displacement from truth dropped 2.7× (q=0.50: 0.00857→0.00323), 3.0× (q=0.60: 0.00761→0.00255), and 6.4× (q=0.80: 0.00984→0.00155) relative to the unsmoothed with-K run — and posterior shapes are genuinely healthy, not just narrower around a different wrong answer (checked histograms directly, not just median+CI, per the bimodality lesson elsewhere in this file): q=0.50 and q=0.60 are clean and unimodal; q=0.80's dominant mode (~700-750/950 samples) sits exactly on truth, with two small satellite bumps at q≈0.78/0.81 — each a full training-grid period away, i.e. outside the current ±half-period smoothing window, not a new failure mode.
  - **Not fully closed.** q=0.50 still has a real, flipped-sign residual bias (+3.4σ, down from -6.2σ) and q=0.80's satellite modes both point the same direction: the current window (± half the grid spacing, 4 offset points) doesn't fully suppress structure a full period away. Natural next step: widen the envelope to ± a full grid spacing (or add more offset points within the same window) and re-check the same 3 points. Also untested: whether the exact-GP+XAS checkpoint (much better native K-calibration per the phase-correction entry above, K/resid²≈0.3-33× vs phase-amplitude's ≈1e3-1e8×) needs this fix at all, or responds differently to it. - **Kernel-level alternative to `k_smoothing_offsets` tried (2026-07-19): one idea disproven before spending GPU time on it, a second idea validated as a real, complementary fix.** Motivated by wanting a training-time (not likelihood-runtime) fix for the same training-grid-periodic K oscillation the entries above address at inference time.
  - **Additive long-lengthscale mass-ratio kernel (`q_floor_kernel`, `heron/models/gp/kernels.py::build_additive_floor_kernel`) — proven NOT to work, both analytically and empirically, before any wiay GPU time was spent on it.** Hypothesis: adding a second, fixed-lengthscale, long-range Matern component alongside the usual short one (`k = k_short + a·k_long`) would keep contributing correlation just off a training node, filling in the posterior-variance dip without shortening the model's effective local lengthscale or inflating noise globally. Wrong: posterior variance at a training node is, to leading order, `Var_post(x_i) ≈ σ²` (observation noise) *regardless of kernel shape* — conditioning on near-noiseless data collapses the posterior to a point mass at that input no matter what prior kernel produced it, a general fact of exact GP regression, not a bug. Worse, the long component barely helps the *antinode* either: any lengthscale long enough to act as a stable floor (not itself prone to collapsing toward `ls_min`, the usual pathology — see the merger-kernel `center`/`width` notes above) is *also* long enough to correlate at ~0.98-1.0 over just half a training-grid spacing, so it explains itself away almost as completely as the short component when conditioned on the same nearby point. Measured directly (two untrained `_ExactGPModel`s, identical fixed noise/outputscale, isolated from MLL training-convergence effects — see `tests/test_gp_q_floor_kernel.py`): node/antinode variance ratio 822.8 with the floor kernel vs. 822.5 without — no real improvement. Kept in the codebase (correctly implemented, PSD, gradient-safe, 16 passing tests) as a documented negative result, not a recommended tool. Reframes the grid-snap fix above: raising `ls_min_q` 0.03→0.06 was bundled with a `noise_floor_rel` 1e-3→1e-2 bump at the time (framed as an incidental numerical-conditioning fix); given that on-node variance is noise-controlled, not lengthscale-controlled, that improvement (variance ratio 500x→1.6-2x) was very plausibly driven substantially or mostly by the noise change, not the lengthscale change — not re-isolated experimentally, an open question.
  - **Directly raising `noise_floor_rel` — validated as a real, complementary fix, independent of `k_smoothing_offsets`.** Since on-node variance is noise-controlled, the natural next experiment was to just raise it further: `noise_floor_rel` 1e-2→5e-2 (one deliberate 5x step past the grid-snap fix's own bump, not the theoretical extreme) on top of the same `ls_min_q=0.06` checkpoint, everything else identical (`examples/train_phenomd_hf_dense30_phase_amplitude_xas_noisefloor.yaml`, `checkpoints/phenomd_nonspinning_dense30_phase_amplitude_xas_noisefloor.pt`, trained on wiay GPU via `condor/dag_noisefloor.dag`). Real cost acknowledged up front: the same `(K+σ²I)⁻¹` term that raises on-node variance also smooths the posterior *mean*, trading some mean-fit fidelity for reduced log-det bias — unlike the kernel-side idea above, this is not a free lunch, and CLAUDE.md's `lsmin0075` entry is the standing cautionary precedent that mean-fit proxies looking fine does not guarantee NS bias improves. NS-validated the same way as `k_smoothing_offsets`, unsmoothed (no `--k-smoothing-grid-spacing`) so the two mechanisms are cleanly separated, at the same three q's: displacement dropped from -6.2σ→**-0.81σ** (q=0.50, ~7.6×), +9.8σ→**+2.9σ** (q=0.60, ~3.4×), -16.0σ→**-6.33σ** (q=0.80, ~2.5×) relative to the unsmoothed `lsminq006` baseline. Checked histograms directly (not just median+CI, per the bimodality lesson elsewhere in this file): all three are clean, single-peaked, unimodal — no bimodality or satellite modes. **Real and complementary, but not fully closed on its own** (q=0.80 in particular is still visibly offset — the histogram's bulk doesn't reach the injected value). Since this mechanism (raising the on-node floor) and `k_smoothing_offsets` (enveloping over nearby offsets) are independent, the natural next experiment is stacking both on the same checkpoint/likelihood call rather than treating them as alternatives. Results: `results/injection_ns_pa_xas_noisefloor_q0{50,60,80}.{npz,png}`.

A follow-up lag-1-autocorrelation check on the high-q log-amplitude residual was itself inconclusive (mean autocorrelation ~0.67, but individual time-columns ranged from -0.3 to +0.99) — genuinely ambiguous, not cleanly resolved. **Given that ambiguity, did not build a data-fit warp against a contested signal** — fell back to a physically-motivated, precedented alternative (`eta(q)`, below) rather than trying to nail an uncertain empirical ℓ(q) profile.
